# Known Bugs

## Open

<!-- Add new bugs at the top of this section -->

- BUG-18 [HIGH] G2P _process_anusvara() is a no-op — method documents anusvara assimilation
  rules but body is just `return word`. Anusvara context-dependent processing is entirely
  missing. Will be critical when switching from gTTS to edge-tts.

- BUG-19 [HIGH] G2P _apply_schwa_rules() is essentially a no-op — only checks SCHWA_EXCEPTIONS
  dict (small) and returns word unchanged. No rule-based schwa deletion for Marathi.

- BUG-23 [HIGH] English-to-Devanagari transliteration (_ENGLISH_TO_DEVNAGARI, ~80 words +
  char-level fallback) only exists in mobile tts_bridge.py. Desktop and Web send raw ASCII
  English words to gTTS/edge-tts which mangles them.

- BUG-25 [MEDIUM] No timeout or retry on gTTS/edge-tts HTTP calls. A single slow/hung request
  blocks the entire TTS pipeline. Mobile streaming especially vulnerable.

- BUG-27 [LOW] Mobile bridge has no temp file cleanup in output/ directory. Stale audio
  files accumulate without age or size limit. Concern on storage-limited Android devices.

- BUG-20 [LOW] No audio caching — repeated identical text fully re-generates audio via
  gTTS/edge-tts API calls every time. Stotras read repeatedly pay full cost each time.

- BUG-21 [LOW] No network connectivity pre-check before gTTS/edge-tts API calls. On mobile
  (flaky network), long timeout before failure instead of immediate user-friendly error.

- BUG-31 [LOW] Bridge error responses use free-text error messages with no structured error
  codes. Kotlin/JavaFX callers must string-match to determine failure type.

- BUG-33 [LOW] number_to_words.py convert_time() has edge case: X:45 without AM/PM produces
  garbled output — includes current hour word before "पावणे" phrase due to fragile index slicing.
