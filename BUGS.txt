## Recently Fixed (Unreleased)

- ~~BUG-72 [CRITICAL] System TTS y-glide pronunciation — anusvara→या, ज→ज्य~~
  (fixed [Unreleased] — SystemTtsEngine used Locale("mr", "IN") which maps to Google's
  Marathi TTS voice with intrinsic y-glide. Switched all Devanagari locales (mr, sa) to
  Locale("hi", "IN") — Hindi voice handles Devanagari without palatalization, same
  approach as edge-tts voice switch (BUG-69 Phase 2). Also added Kotlin-side pronunciation
  preprocessing: ज्ञ→द्न्य, ॐ→ओम्, avagraha expansion, visarga r-sandhi before voiced
  consonants, Vedic accent stripping, abbreviation expansion.)

- ~~BUG-73 [HIGH] Streaming hangs — concurrent UtteranceProgressListener overwrite~~
  (fixed [Unreleased] — SystemTtsEngine.synthesize() now wraps with synthMutex.withLock
  so only one synthesis call uses the UtteranceProgressListener at a time. Without this,
  Semaphore(3) concurrent chunks overwrote each other's listeners, causing continuations
  to never resume and hang at 30s timeout.)

- ~~BUG-70 [CRITICAL] Audio stops when switching tabs — OutputFragment.onDestroyView()
  killed playback~~
  (fixed [Unreleased] — OutputFragment created a local AudioPlayerService and called
  audioPlayer.stop() in onDestroyView(). When user switched to Input or Me tab, the
  Fragment was destroyed, stopping audio immediately. Fix: moved AudioPlayerService to
  activity-scoped PlaybackViewModel. OutputFragment now delegates to PlaybackViewModel
  for all playback. onDestroyView() no longer stops audio. Mini-player bar shows
  persistent playback controls across all tabs. FEAT-81/82.)

- ~~BUG-69 [HIGH] ZWNJ insertions in edge-tts paths caused pronunciation artifacts~~
  (fixed [Unreleased] — Phase 1: apply_gtts_mr_fixes() was designed for gTTS concatenative
  synthesis but was applied to all edge-tts neural paths. ZWNJ insertions confused
  the neural model. Fix: created apply_edge_tts_fixes() with only chandrabindu +
  halant rules, no ZWNJ. Updated all 6 edge-tts functions across mobile + desktop.
  Phase 2: ZWNJ removal alone did not eliminate ज→ज्य / च→च्य y-glide — the
  Marathi neural voices (mr-IN-AarohiNeural, mr-IN-ManoharNeural) have intrinsic
  palatalization in their training data. Fix: switched _EDGE_VOICE_MAP for "mr" and
  "mr-old" from mr-IN to hi-IN voices (hi-IN-SwaraNeural, hi-IN-MadhurNeural).
  Hindi voices handle Devanagari correctly without y-glide. Also added defensive
  ZWNJ/ZWJ/ZWS stripping in apply_edge_tts_fixes(). Also fixes BUG-49 male voice.)

- ~~BUG-68 [HIGH] Accent/gender chips hidden behind collapsed "Options" toggle on Input screen~~
  (fixed [Unreleased] — after moving accent/gender from Output to Input screen, the chips
  were placed inside the options_card MaterialCardView which starts with visibility="gone".
  Users had to tap an "Options" button to reveal them. Fix: set options_card visibility to
  "visible" by default and optionsExpanded=true in the InputFragment.)

- ~~BUG-67 [CRITICAL] Prosody word highlighting broken — PauseType IntEnum not JSON-serializable~~
  (fixed [Unreleased] — analyze_prosody() in tts_bridge.py returns prosody segments with
  seg.pause_after_ms as a PauseType IntEnum. Chaquopy serializes this as
  "<PauseType.COMMA: 180>" instead of 180, causing JSON parse failure on the Kotlin side.
  PythonBridge.call() fails with "Unterminated object at character 117" → no prosody
  segments → no word highlighting during playback. Fix: explicitly cast to int/bool/str
  in the result dict: int(seg.pause_after_ms), bool(seg.is_verse), str(seg.metre_name).
  Applied to both mobile and desktop bridges.)

- ~~BUG-66 [CRITICAL] Streaming produces only 1-2 chunks — progressive playback causes
  fragment recreation and coroutine cancellation~~
  (fixed [Unreleased] — BUG-65's progressive playback set isLoading=false after the first
  chunk, which triggered autoPlay with only 1 file. When the user switched tabs, the Fragment
  was recreated (ViewModel survives) but the coroutine job received JobCancellationException,
  killing all remaining streaming chunks. The re-created Fragment's autoPlay then played
  with only 2 available chunks. Fix: reverted to wait-for-all approach — isLoading stays
  true until ALL chunks complete, then isLoading=false + full streamChunks list triggers
  a single autoPlay with the complete queue.)

- ~~BUG-61 [MEDIUM] No catch block in streaming coroutine — silent failures~~
  (fixed [Unreleased] — generateStreaming() had try/finally but no catch block.
  If an unexpected exception occurred (e.g. Chaquopy init failure), the error state
  was never set and the UI stayed stuck on "Streaming: preparing N chunks…" forever.
  Fix: added catch(e: Exception) that sets error state and logs the exception.
  Same fix applied to generateSingle().)

- ~~BUG-62 [BLOCKER] fragment_input.xml had duplicate view IDs — app failed to build~~
  (fixed [Unreleased] — the Input screen reorder intended to move source chips above
  the text box, but instead duplicated the chip_group_sources, btn_options_toggle,
  options_card, spinner_language, and switch_verse views. This caused a data binding
  error ("conflicts with another tag that has the same ID") and the app could not
  compile. All previous fixes (BUG-57/58/59, BUG-60/61) were never deployed because
  the build was broken. Fix: removed the duplicate XML block.)

- ~~BUG-60 [CRITICAL] Streaming UI stuck in loading state — postValue race condition~~
  (fixed [Unreleased] — generateStreaming() used _state.postValue() for progress
  updates and _state.value for the final success state. Since postValue is async
  (queued on the main handler), the stale progress update arrived AFTER the final
  setValue, overwriting streamChunks/isLoading with stale values. This made the UI
  appear stuck in "Streaming: N of M" forever with the player card hidden, even
  though audio was actually generated. Fix: replaced all postValue() calls with
  direct setValue() — safe because the coroutine runs on Dispatchers.Main.)

- ~~BUG-59 [MEDIUM] Desktop queue playback stalls on corrupt/missing chunk files~~
  (fixed [Unreleased] — AudioPlayerUtil.playQueueInternal() had no setOnError handler, so
  a corrupt or missing chunk file would cause playback to stall indefinitely. Fix: added
  file existence check before playback and setOnError handler that skips to next chunk.)

- ~~BUG-58 [MEDIUM] Desktop streaming progress counter inflated — counts failed chunks~~
  (fixed [Unreleased] — in runStreamingGeneration(), completedCount.incrementAndGet()
  was called BEFORE checking result["success"], so failed chunks were counted as
  successful. Fix: moved counter increment inside the success branch.)

- ~~BUG-57 [CRITICAL] Streaming loses UI state (accent, gender, prosody, emotion intensity)~~
  (fixed [Unreleased] — both generateSingle() and generateStreaming() in OutputViewModel
  replaced _state.value with a brand-new OutputState(), discarding all existing state
  including prosodySegments, accent, gender, emotionIntensity, isVerseDetected, and
  detectedMetre. This caused the prosody preview to disappear and user-selected accent/
  gender to reset. Fix: replaced all OutputState() assignments with .copy() to preserve
  existing state. Also fixed streaming progress counter to only count successful chunks,
  and added error logging for chunk failures.)

- ~~BUG-55 [HIGH] Old Marathi verse + edge-tts combination never calls stotra preprocessing~~
  (fixed [Unreleased] — in _generate_edge_tts(), the if-elif structure for language == "mr-old"
  did not include _preprocess_stotra_text() for verse mode. Fix: added _preprocess_stotra_text()
  call when is_verse=True for Old Marathi in both mobile and desktop bridges.)

- ~~BUG-54 [HIGH] _normalize_marathi() missing for Old Marathi in all edge-tts paths~~
  (fixed [Unreleased] — Unicode NFC normalization (BUG-29 fix) was being skipped for Old
  Marathi in _generate_edge_tts(), _generate_edge_prosody(), and _generate_edge_verse_prosody().
  This caused unnormalized text to reach phonetic processing. Fix: added _normalize_marathi()
  before apply_old_marathi_phonetics() in all edge-tts code paths on both mobile and desktop.)

- ~~BUG-53 [CRITICAL] Content classifier, prose preprocessing, and grammar engine all skipped
  when edge-tts succeeds~~
  (fixed [Unreleased] — in generate_tts(), the content-type adaptive preprocessing (FEAT-18),
  abbreviation expansion, English transliteration, and grammar engine were all positioned AFTER
  the edge-tts block. Since edge-tts returns early on success (which is the common path for users
  with internet), none of these preprocessing steps were ever applied. Fix: moved all three
  preprocessing blocks (content classifier, prose preprocessor, grammar engine) BEFORE the
  network check and edge-tts block in both mobile and desktop bridges.)

- ~~BUG-56 [MEDIUM] Sanskrit anusvara only assimilated before sibilants, not varga stops~~
  (fixed [Unreleased] — SandhiEngine.fix_anusvara_sibilant() only handled anusvara before
  शषसह but not before varga stop consonants (कखगघ, चछजझ, etc.). Added new
  fix_anusvara_varga() method using class-nasal mapping: anusvara before velar→ङ्,
  palatal→ञ्, retroflex→ण्, dental→न्, labial→म्. Synced across all 3 platforms.)

- ~~BUG-52 [HIGH] ज्ञ pronounced as ग्य (Hindi) instead of द्न्य (Marathi) in verse paths~~
  (fixed [Unreleased] — all verse code paths (edge-tts verse prosody, edge-tts single-call,
  gTTS verse) for default language "mr" skipped `apply_marathi_phonetics()`, so the
  ज्ञ→द्न्य replacement was never applied. Only prose paths called it. Fix: added
  `apply_marathi_phonetics()` to all verse paths for default Marathi in both mobile and
  desktop bridges. Also added `_normalize_marathi()` + `apply_marathi_phonetics()` to
  edge-tts prose prosody and single-call paths.)

- ~~BUG-51 [HIGH] Y-glide persists on word-final matra+anusvara despite BUG-48 ZWNJ fix~~
  (fixed [Unreleased] — ZWNJ insertion between consonant and matra (BUG-48) was insufficient:
  both gTTS and edge-tts neural models still produced y-glide [j] on words like संतीं→संतीय,
  द्यावें→द्यावेय. Root cause: ZWNJ only breaks grapheme clusters but doesn't change how
  the TTS model phonologizes nasalized vowels at word boundaries. Fix: added new rule in
  apply_gtts_mr_fixes() that replaces word-final matra+anusvara with matra+chandrabindu
  (ं→ँ) at word boundaries, marking pure vowel nasalization without nasal consonant onset.
  Also applied apply_gtts_mr_fixes() to ALL edge-tts paths (was previously gTTS-only).)

- ~~BUG-50 [HIGH] Accent profiles produce no audible difference — offsets too small + threshold blocks them~~
  (fixed [Unreleased] — two root causes: (A) `needs_fx` threshold `>0.05` discarded most accent
  pitch/speed changes (northern had -0.02 pitch, -0.05 rate — both at or below threshold);
  (B) offsets were 2-8% which is below human perceptual threshold. Fix: lowered all needs_fx
  thresholds from >0.05 to >0.01 across verse/prosody/Stage1 paths; expanded accent offsets to
  10-18% range; added 5 new Maharashtra regional profiles (Pune, Kolhapuri, Vidarbha, Malvani,
  Marathwada, Khandeshi, Konkan) replacing generic northern/konkanastha/deccani.)

- ~~BUG-48 [MEDIUM] gTTS y-glide on ALL nasalized matras — not just front vowels~~
  (fixed [Unreleased] — apply_gtts_mr_fixes() only blocked y-glide for ें/ैं (front-vowel
  matras + anusvara). Extended ZWNJ insertion pattern from [\u0947\u0948] to [\u093E-\u094C]
  to cover ALL matras (ां ीं ूं ों ौं etc.) before anusvara. Fixes Old Marathi verse
  endings like संतीं→संतीय, द्यावें→द्यावेय, तयां→तयाय.)

- ~~BUG-47 [HIGH] Schwa deletion lexicon never matches Devanagari words — \b word boundary broken~~
  (fixed [Unreleased] — Python re \b treats Devanagari matras (ा ी ू etc.) as \W, so \b
  matches INSIDE words rather than at word edge.  Replaced regex-based lookup with
  token-splitting approach.  Also expanded _SCHWA_DELETION_LEXICON from ~20 to ~200 entries
  and added rule-based medial schwa deletion for unlisted common Marathi words.)

- ~~BUG-46 [CRITICAL] Verse mode crashes app — speed slider stepSize=0.1 incompatible with 0.85 value~~
  (fixed [Unreleased] — changed slider_speed stepSize from 0.1 to 0.05 in fragment_output.xml
  so 0.85 (= 0.5 + 7×0.05) is a valid step position. FEAT-48 smart verse speed sets 0.85x.)

- ~~BUG-43 [HIGH] TTS generation permanently locks after first attempt — hasStartedGeneration never reset~~
  (fixed [Unreleased] — wrapped generateSingle() and generateStreaming() in try/finally to always
  reset hasStartedGeneration flag; also reset in cancelGeneration(). Verse mode was most visibly
  affected because complex prosody failures trigger the flag lockout immediately.)

- ~~BUG-44 [MEDIUM] Long Marathi prose not streaming — splitSentences() regex fails on common punctuation~~
  (fixed [Unreleased] — unified regex to `(?<=[।॥?!.;])\s*` so periods/semicolons split without
  requiring trailing whitespace; added fallback comma/newline splitting for unpunctuated prose.)

- ~~BUG-45 [MEDIUM] text_normalizer.py eyelash-ra regex uses \\u escapes in raw strings — causes re.error~~
  (fixed [Unreleased] — replaced `r'(\\u0915)-(\\u0939)'` / `r'\\1\\u0931\\u094d\\2'` with actual
  Devanagari characters `r'(क)-(ह)'` / `r'\\1ऱ्\\2'` in all 3 platforms per coding standard.)
